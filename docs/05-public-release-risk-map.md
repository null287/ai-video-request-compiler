# 公开仓库法律与公开风险矩阵

> 这是一份发布前的风险分层工具，不是法律意见。它只帮助区分“内容是否敏感”和“是否有权公开/授权”，不能替代对劳动合同、保密协议、适用发布政策或第三方许可的核对。

## 一、风险分层

| 等级 | 内容类型 | 处理方式 |
| --- | --- | --- |
| 红色：禁止公开 | 内部链接、账号、密钥、客户资料、真实需求单、投放数据、预算、人员信息、组织代码、后台截图、真实素材 | 从公开仓库删除；不要只打码后继续使用 |
| 橙色：必须确认 | 工作期间形成的具体文字、特定组织内部文档的独特表达、基于内部资料的流程细节、第三方 Prompt/代码/图片/声音、组织 Logo 与商标 | 获取书面授权或彻底改写为通用方法；没有授权不进入公开分支 |
| 黄色：建议改写 | 精确模型名称、平台限制、批次编号、内部角色名称、可回溯的项目时间线、未经公开证据支持的成果数字 | 改为工具无关、项目无关的占位表达 |
| 绿色：可公开 | 通用概念、抽象字段、虚构案例、公开来源链接、对方法的概括性解释 | 保留，但仍应标明许可与适用边界 |

## 三、为什么“没有特定组织信息”仍不能自动等于零风险

### 1. 商业秘密风险

公开材料是否构成商业秘密，不能只看有没有特定组织名称，还要看信息是否不为公众所知、具有商业价值，以及权利人是否采取了保密措施。违反保密义务披露、使用或允许他人使用相关信息，可能产生风险。参见[《反不正当竞争法》第十条](https://www.npc.gov.cn/npc/c2/c30834/202506/t20250627_446247.html)。

### 2. 职务成果与著作权风险

如果具体文字是在完成单位工作任务时创作，或者合同约定著作权/发表权归单位，公开发布和向社区授予许可可能需要单位确认。参见[《著作权法》第十八条](https://www.npc.gov.cn/c2/c30834/202011/t20201119_308796.html)。

方法思路与具体文字的权利状态需要分别判断。公开版采用工具无关、项目无关的通用重写，不应原样上传来源或权利状态不明的工作文件。

### 3. 保密与竞业约定风险

劳动合同或保密协议可能另行约定商业秘密和与知识产权有关的保密事项。参见[人力资源和社会保障部发布的《劳动合同法》文本](https://www.mohrss.gov.cn/xxgk2020/fdzdgknr/zcfg/fl/202011/t20201102_394622.html)。

### 4. 个人信息与第三方素材风险

真实姓名、头像、联系人、工号、声音、肖像、未成年人信息、健康/金融信息，以及客户素材、字体、音乐、Logo 和参考视频，都不能因为“只是示例”就直接公开。公开版应使用虚构内容、抽象占位符或明确许可的素材。

## 四、推荐的最低风险公开路径

1. 公开版只放通用重写稿，不放任何特定组织的原始文件。
2. 不把包含原始文件的本地 Git 分支推到远程。
3. 不公开特定组织名称、内部项目、平台账号、生产数据和真实案例素材。
4. README 仅说明这是工具无关的公开方法，不代表任何特定组织或团队。
5. 许可证只适用于你有权授权的原创内容，不适用于特定组织或第三方材料。
6. 在外部引用中，将链接标注为“公开方法参考”，不要标成任何组织的“官方规范”或“官方仓库”。
7. 公开前保留合同/政策核对结果；如果无法确认，先只创建私有仓库或只在本地保存。

## 五、发布前停止条件

出现以下任一情况，就先不要公开推送：

- 发现公开分支仍含真实组织资料、内部链接、截图或交付内容；
- 无法判断某一段具体文字是否来自特定组织原文或既有工作任务；
- 需要把第三方素材、代码或模板逐字放入仓库；
- 不能确认自己有权授予公众复制、修改和再分发许可；
- 权利人明确禁止对外发布，或合同/保密协议存在相反约定。
