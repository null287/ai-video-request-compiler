# 公开发布安全清单

本清单用于把既有实践整理成公开方法论时做最后一次检查。它不是法律意见；涉及雇佣合同、保密协议、著作权归属或发布授权时，应向有权限的权利人或专业律师确认。

## A. 组织与商业秘密

- [ ] 没有特定组织名称、项目代号、客户名称或内部产品名称
- [ ] 没有内部 URL、账号、邮箱、密码、Token、Cookie 或截图
- [ ] 没有真实需求单、交付记录、投放数据、KPI、预算数字或人员信息
- [ ] 没有复制特定组织 SOP 的独特措辞、内部编号或未公开流程细节
- [ ] 没有组织代码、内部接口、数据库结构、系统页面或私有 Skill
- [ ] 已核对劳动合同、保密协议、适用的发布/开源政策
- [ ] 已确认自己有权公开并授权仓库中的文字、图片、代码和示例

## B. 著作权与第三方内容

- [ ] 公开版是抽象重写，不是把内部文件原样搬运
- [ ] 所有示例人物、品牌、产品、画面、音乐、字体和 Logo 都是自有、已获授权或完全虚构
- [ ] 没有把参考视频下载、截图或关键帧直接放进仓库
- [ ] 没有复制其他开源仓库的代码、模板正文或许可证文本
- [ ] 第三方参考只保留链接、名称和“参考思路”说明，并遵守其许可证
- [ ] 仓库许可证与实际权利范围一致，不把无权授权的组织材料授予公众

## C. 个人信息与隐私

- [ ] 删除真实姓名、头像、联系方式、工号、群成员、客户联系人和可识别截图
- [ ] 删除真人肖像、声音、面部特征、未成年人信息和健康/金融等敏感信息
- [ ] 对案例中的人物、组织、数字和链接使用虚构或不可回溯占位符

## D. 事实与署名

- [ ] README 明确这是个人脱敏方法论，不代表任何特定组织或团队
- [ ] 没有把团队成果写成个人独立完成
- [ ] 没有声称上线、获奖、指标提升或组织采纳，除非有可公开证据
- [ ] Git 提交作者、时间和变更说明准确
- [ ] 版本号、变更记录和许可证状态清晰

## E. 推送前技术检查

```text
git status
git diff --check
git grep -n -I -E "token|api[_-]?key|password|secret|cookie|内部|客户|工号|@"
node scripts/build-content-bundle.mjs --check
```

检查结果不能替代人工审阅；尤其要逐页看 Markdown、图片元数据、历史提交和仓库设置。
